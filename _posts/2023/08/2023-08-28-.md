ネットワークのトラブルが発生して数時間を消費した。

問題に気づいたのはまだ起き上がる前だった。目が覚めてはいたけどまだ意識がはっきりしていないときに揺れたような気がした[^1]ので、布団で寝ながら防災速報アプリを開いた。するとネットワークエラーで情報を取得することができなかった。防災速報だけがそうなっている可能性もあるので別のアプリ (GitHub) を開いてみたらこちらもネットワークエラーだった。

[^1]: 結果的には地震は来ていなくてただの勘違いだった。

さてはまた Raspberry Pi のせいだなと思い調べてみたら、たしかに Raspberry Pi に問題があったのだが、今回は今までとは少し違った。実はここ数日、たまにインターネットにつながらない現状が局所的に発生することがあったんだけど、それはファイアウォールなどの関係でフォワーディングがうまくいっていなかったりすることに起因していた。だから今までの場合だと Raspberry Pi ではインターネットにつながっているけど Mac や iPhone では接続できないという問題だった。

しかし今回は Raspberry Pi でもインターネットにつながらなかった。しかも不思議だったのはローカルネットワークはすべて疎通がうまくいっているのにインターネットにだけつながらないという状況だった。

でもおかしい。名前解決がうまくいっていないなら Dnsmasq が落ちていたりすることが原因になるが、TCP/IP レイヤーはそこまでいじっていないので問題になるところが限られている。ファイアウォールを一時的に無効にしても変わらなかったし、設定ファイルが勝手に変わってしまっているということもなかった。

問題が発覚した 10 時半前から 11 時半前くらいまでは、なんとかその原因を探ろうとしていたのだが、全く原因が見つからない上に、実は今日は 11 時半からミーティングがあったのでそれに参加しないといけなかった。だから、結局原因はなんだったのかわからなくなってしまうが、最悪再起動すれば直るだろうと思い諦めて再起動したのだが、なんと今回は再起動しても問題が解決しなかった……！！

いよいよ原因を調べないといけない状況になり、次はどこかの周辺機器が壊れていることを疑った。そのために壁の LAN と ELECOM の Wi-Fi ルータを直接つないでみた。するとインターネットに接続することができた。Raspberry Pi で使用している全部のケーブルでそれを試してみたが、いずれも問題なく接続できた。

さらに、Nintendo Switch で使っている USB-LAN アダプタを Raspberry Pi 側で拝借して使ってみたところ、ローカルでのデバイス間通信はできたがインターネットの接続はできなかった。つまりもともと Raspberry Pi 側で使っていた USB-LAN アダプタにも問題はないということがわかった。

つまり、機器の故障ではないというところまでは断定できた。また、Wi-Fi ルータと直接接続するとインターネットにつながるから、やっぱり問題は Raspberry Pi の内部にあるということが分かった。

しかしここまで分かったものの、じゃあ原因はなんなのかを見つけるのはかなり時間がかかった。唯一違うところは、Raspberry Pi ではプロバイダ側で用意されているネットワークの IP アドレスのレンジ内で固定の IP アドレスを割り振っていた。つまり DHCP は無効にした状態で使っていた。[一応、Raspberry Pi に割り振っていたものも、ELECOM の Wi-Fi ルータと直接つないだときに Mac に自動で割り振られたものも同じサブネットマスク内にあった](https://www.fg-products.com/downloads/fgn-r2_manual.pdf)のでやっぱり問題はないよなあと思いつつも、他に全く手がかりがないので、固定ではなく DHCP を使って接続するように Netplan の設定を変更してみた。

https://cosmoz.jp/usage/netconf.html

すると Raspberry Pi でもインターネットが復活した！ つまりプロバイダ側のインターフェースで固定 IP アドレスにしてしまっていたのが問題だったらしい。DHCP を使うことで解決することができた。

ちょうど 14 時ごろに直った。問題に気づいて調査を始めたのは 10 時半くらいだから直すのに 3 時間半くらいかかった。問題に気づいたのは 10 時半前くらいなのだが、それより前に出勤は問題なくできていたので 10 時前の時点では問題なかったことになる。だからここの間に何かがあったことになる。

しかし今までずっと問題なかったのに急に問題が発生するというのはどういうことなんだろうという疑問は残った。もしかしたらプロバイダが今日の午前中のタイミングでデフォルトの IP アドレスのレンジを変えた疑惑がある。一応、それを確かめるために、壁の LAN ポートの下にあった QR コードからサポートページにアクセスし、問い合わせメニューから以下のような問い合わせを送ってみた。

>マンション備え付けの FGBB の回線 (壁埋込式) を利用しています。
>
>今まで問題なく利用できていましたが今日の午前中（おそらく 10 時台）あたりから急にインターネットに接続できなくなってしまいました。結果的には DHCP を使用すること>でこの問題はすでに解決したのですが、今日になって突然使えなくなったことが不可解であるのと固定 IP アドレスが使えないのが不便です。
>
>今回お問い合わせさせていただきたい内容は以下のとおりです。
>
>今日の午前中あたりにそちら（プロバイダ）側で有効な IP アドレスのレンジの変更等、何かの設定を変更されましたでしょうか？
>
>今までは DHCP を使用せず、以下を固定で設定していました。
>
>ルータの IP アドレス: 192.168.150.1
>サブネットマスク: 255.255.255.0
>問題が発生した機器に割り振っていた固定 IP アドレス: 192.168.150.2
>
>また、Wi-Fi ではなく有線接続（FGBB の壁にある LAN ポートからの接続）をしていました。
>
>ご回答よろしくお願いいたします。

https://supportcenter1201.ivr.mobilus.me/1/fgbb

これは回答待ち。ちなみにここのフォーム、500 文字までしか入らないらしいのだが、500 文字入れていないのに 500 文字のエラーが出てしまった。ギリギリだとダメらしい。本当適当だなあ。

途中でプロバイダが提供している備え付けの Wi-Fi を使ってみたりして、最初はこれもつながっていたけど、その後、壁の LAN ポート付近にあるリセットボタンを押してから Wi-Fi が使えなくなってしまったり、Netplan の設定を削除して `sudo netplan apply` して SSH から締め出されてしまったり (ELECOM Wi-Fi → Raspberry Pi → Mac, iPhone というつなぎ方にして `arp-scan` で Raspberry Pi の新しい IP アドレス (DHCP) を探してなんとか解決した) といろいろ問題も多かったが、なんとか解決して良かった。

プロバイダ側で設定を変えたのなら今回の問題発生にも納得できるのだが、もしそうじゃなかった場合はなんで今日の午前中に突然この問題が発生したのか本当に疑問だ。しかしいずれにしてもプロバイダがデフォルトで提供している IP アドレスのレンジを固定で設定すると、引っ越したときに毎回そこの IP アドレスの設定を更新しないといけないから汎用性がないよなあとは設定当初から思っていた。だから今回、プロバイダ側に直接つながっているインターフェース側の IP アドレスを DHCP で動的にすることでそこの問題も副次的にクリアできたのでまあ結果的には良かったのかな。

ちなみに仕事のほうだが、もちろん 11 時半には間に合わなかったので iPhone の Slack で (モバイル通信を使って) ネットワークトラブルが起きているから参加できないということを報告した。また、そのあともずっとつながらなかったのでこのまま問題が解決しなかったら今日はもう退勤すると言っておいた。結果、14 時には直ったのだが、このことをここに書かなきゃいけないとかネットワークの設定を GitHub に反映しないといけないとか、その他 cron の設定とかもろもろやりたいことが山積みで、そこから仕事復帰しますというとなんかタスク降ってきたりしてめんどくさいから、直ったけど直っていない (というか一応全く繋がらない状態は解消されたけど不安定だからという理由にして) と言って早退した。全く繋がらないと言ってしまうと会社の PC から退勤したことを追跡されていた場合に嘘じゃんとバレてしまうから一応整合性をとっておこうと思って。
